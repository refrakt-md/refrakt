# v0.41.1 — Readable release notes

The changelog on the site now opens each release with a short summary of what it is for,
links the specs and bugs behind it as drawers, and folds the full list of changes underneath
({% ref "SPEC-176" /%}). This release also fixes `plan validate --against`, which missed an ID
collision with anything `main` created after a branch split off ({% ref "BUG-040" /%}), and
`plan create milestone`, which named the file after the title instead of the version
({% ref "BUG-041" /%}).

## Why

**The changelog was written for someone reading a diff.** Every entry was a flat list of
changeset bullets, around 30 for v0.41.0, with nothing to say what a release was for or what
a user had to change after upgrading. The plan already records that for every minor release,
so the page can say it.

**The pre-merge collision check let through the collision it exists to catch.** Two branches
that each take the next free ID pass `plan validate --against`, and the duplicate only
surfaces after the merge, when every reference to the ID is already ambiguous. It was found
while this milestone's own spec and work items collided with `main`.

## What lands

- **The generator** ({% ref "WORK-641" /%}): notes from `releases/notes/`, the milestone's
  opening as a fallback, changeset detail inside `{% details %}`.
- **A check on notes** ({% ref "WORK-642" /%}): every ref in a note resolves to a plan
  entity.
- **A draft command** ({% ref "WORK-643" /%}): `npm run release-notes:draft` writes
  everything but the opening sentences.
- **The backfill** ({% ref "WORK-644" /%}): notes for v0.39–v0.41, blog links for v0.4–v0.9,
  and a review of every milestone opening used as a fallback.
- **Two plan CLI fixes:**
  - {% ref "BUG-040" /%}: the merge-base tells a branch-side deletion from a base-side
    addition;
  - {% ref "BUG-041" /%}: a new milestone is filed as `<name>.md`, and
    `plan migrate filenames` repairs one that is not.

## Sequencing

WORK-641 first; WORK-642 and WORK-643 can follow in parallel, then WORK-644. BUG-040 and
BUG-041 are independent and can land at any point.

## Deliberately not here

- Making `refrakt validate --deep` report unresolved refs, and the look and build-log volume
  of unresolved refs inside drawers (SPEC-176 non-goals).
- Release notes in the npm or GitHub release bodies.
