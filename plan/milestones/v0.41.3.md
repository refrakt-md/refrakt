# v0.41.3 — A fresh scaffold works

A project made with `create-refrakt` builds with no errors, and the HTML starter runs the
plugins it is configured with. Building plan content no longer slows down with the length of
the repository's git history, and a sandbox receives the design tokens the pipeline injects.

## Why

**The first thing a new user sees is an error they did not cause.** Five of the six starters
link a nav item to a page that does not exist ({% ref "BUG-035" /%}). The HTML starter never
passes `plugins` to `loadContent`, so cross-page features are empty with no warning
({% ref "BUG-036" /%}). Both were found by {% ref "WORK-634" /%}'s scaffold tests, and v0.41.0
is the release that invites users to write their own runes. These are fixes, so they ship as
a patch rather than waiting for v0.42.0.

**CI passes only because its clone is shallow.** On a full-history clone, two tests that
build real plan content take about 170s, against about 17s on a shallow one
({% ref "BUG-043" /%}). Any full-history build of a site with plan content pays the same cost.

## What lands

- {% ref "BUG-035" /%}: the five starters link `docs/getting-started`, and a scaffold test
  builds each template and asserts no errors.
- {% ref "BUG-036" /%}: the HTML starter loads its configured plugins, and a scaffold test
  asserts that a plugin hook ran.
- {% ref "BUG-043" /%}: history extraction stops starting one process per commit and file, and
  the pipeline test stops depending on the clone it runs in.
- {% ref "BUG-034" /%}: the sandbox behaviour and the token producers use one channel. This
  changes what every sandbox renders on a site with a default `design-context`, so it needs its
  own changeset line.

All four are independent.
