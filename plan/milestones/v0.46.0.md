# v0.46.0 — The theme contract

A theme renders a vocabulary and configures no rune ({% ref "ADR-043" /%}); a plugin rune speaks
the same vocabulary, and only its novel parts bring their own structure, in tokens
({% ref "ADR-044" /%}). Both decisions were accepted on 2026-10-28. This milestone builds what
makes them checkable.

## Why

**Themes can still change what a rune means.** A theme can override a native rune's field labels,
sentiment mapping and formatting (`metaFields.*.label`, `sentimentMap`, `transform`), which are
claims about content.

**The engine still decides a look.** It gives `status`, `category` and `tag` values the
`rf-badge` class, so the pill is the engine's, not the theme's.

**Nothing says whether a theme is complete.** Lumina's coverage test checks BEM selectors per
rune. A theme for composed runes needs to cover the vocabulary instead, and a plugin needs to
know which of its elements no theme will style.

## What lands

Six items:

- **Themes:**
  - {% ref "WORK-670" /%}: all of `metaFields` is identity;
  - {% ref "WORK-671" /%}: the engine stops adding `rf-badge`; pills move to skeleton;
  - {% ref "WORK-672" /%}: the theme vocabulary coverage check.
- **Plugins:** {% ref "WORK-673" /%}: a vocabulary report per plugin rune, a token-only lint, and
  the plugin guide rewritten around ADR-044's tiers.
- **Narrative fields** ({% ref "ADR-047" /%}):
  - {% ref "WORK-674" /%}: the checks at definition load;
  - {% ref "WORK-675" /%}: the content-boundaries guide.

## Planning state

Drafted on 2026-10-28. Every item is `ready`. The guard against a theme overriding a composed rune
({% ref "WORK-669" /%}) went into v0.44.0 instead, because that milestone adds the first composed
runes a theme could target.

**It can run alongside v0.45.0.** No item here depends on the ladder, and the two touch
different files, except that WORK-672's coverage list includes `ladder` once v0.45.0 ships it.

## Breaking changes

- **WORK-670:** a third-party theme overriding `label`, `sentimentMap` or `transform` has the
  override reported and dropped. No first-party theme does.
- **WORK-671:** field values lose the `rf-badge` class. A theme that keyed on it moves to
  `[data-meta-type]`. Lumina and skeleton move in the same change.

## Sequencing inside the milestone

- WORK-671 before WORK-672, so the coverage check starts from the vocabulary rules, not the
  engine's class.
- WORK-674 before WORK-675, so the guide describes the checks that exist.
- WORK-670 and WORK-673 are independent.

## Deliberately not here

- **`formats`** ({% ref "SPEC-166" /%} D6). It ships with the first value kind, so it waits for
  the value primitives, whose specs ({% ref "SPEC-162" /%}, {% ref "SPEC-165" /%}, SPEC-166) are
  drafts and not yet reviewed.
- **Theme and site templates** ({% ref "SPEC-177" /%}), which wait on their prerequisites.
- **Draining Lumina's per-rune CSS.** It follows each rune's composition, not this milestone.
