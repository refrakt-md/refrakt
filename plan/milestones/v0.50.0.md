# v0.50.0 — Nothing reads a class

Every fact the output carries is a data attribute, and nothing but a stylesheet reads a class.
This is step 1 of {% ref "ADR-048" /%}'s implementation order: the parts of {% ref "SPEC-196" /%}
that depend on nothing else, done first because every later step relies on them.

## Why

{% ref "SPEC-196" /%} D1 makes the data attributes the output's contract and classes the theme's
choice. Today two things stop that from being true:

- **Some facts exist only as a class.** A context modifier (`rf-actions--in-bar`) says which rune
  an element sits in, and nothing else says it. A theme without classes would lose it.
- **Code reads classes.** 27 selector sites in `@refrakt-md/behaviors` and 2 in the Svelte
  components find elements by `.rf-` class, and 4 behaviours write classes onto elements a rune
  owns. Because the prefix is configurable, these already break for a theme with another prefix:
  a latent bug, whatever the `classes` setting later decides.

Until both are fixed, the `classes` setting ({% ref "SPEC-196" /%} D2, step 4) cannot offer
`"none"` or a mapping table, and a domain rune cannot drop its classes when it becomes a
definition.

## What lands

Five items. Every change adds and none removes: no existing selector stops matching, the HTML gains
attributes and loses no class, and nothing changes for authors.

- {% ref "BUG-048" /%}: the menubar nav behaviour finds its groups again. First, on its own.
- {% ref "WORK-722" /%}: `data-in` and `data-tinted` (D5), and the context- and static-modifier
  CSS reads attributes.
- {% ref "WORK-723" /%}: behaviours and components select by attribute (D6), and a test fails on
  any `.rf-` selector there.
- {% ref "WORK-724" /%}: behaviours write state as `data-state`, not as classes on rune-owned
  elements (D6).
- {% ref "WORK-725" /%}: the UI behaviours build carries `data-name`, and its CSS moves to it.
  Lowest priority: nothing breaks if it slips to a later milestone.

## Sequencing inside the milestone

- BUG-048 first. WORK-723 rewrites the same selector, and the bug should land with its own test.
- WORK-722 and WORK-724 are independent of the rest.
- WORK-725 follows WORK-723, which gives `data-name` to the elements its own selectors need.

## Deliberately not here

- **The `classes` setting and `role`** ({% ref "SPEC-196" /%} D2, D3 and D8): step 4 of
  {% ref "ADR-048" /%}. This milestone only makes it possible.
- **The `data-rune` renames** (D10): each ships with its rune's definition.
- **The hand-built rune markup in resolvers** (`xref-preview-resolve.ts`, `file-ref-resolve.ts`,
  `collection-helpers.ts`): {% ref "SPEC-194" /%} replaces it by placing the real runes.
- **The vocabulary and primitives work** (step 2) and every rune conversion.
