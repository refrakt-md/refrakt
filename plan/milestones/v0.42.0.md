# v0.42.0 — What a composition can express

Since v0.41.0, anyone can write a composed rune. This milestone widens what a definition can
say. Templates may be indented, and `refrakt format` indents nested runes for you. Content may be split on `---` into named zones, a sections
model may treat content with no headings as one section, and `each` can walk the items of a
plain list. An `itemModel` declared in YAML now extracts its fields instead of leaving every
one empty ({% ref "SPEC-169" /%}, {% ref "SPEC-170" /%}).

## Why

**The first problems people writing definitions hit are in the parser.**

- Indenting a template, the obvious way to read nested runes, silently turns it into a code
  block.
- A YAML `itemModel` binds empty `$each` fields with no error ({% ref "BUG-038" /%}).

**Five runes are blocked on one content model.** `hero`, `feature`, `step`, `recipe` and
`playlist` split on `---` and address fields inside a zone. Without `type: delimited` none of
them can become a composition, and SPEC-145 D18's claim that recipe's model "is declarable in
frontmatter" is untrue. `implicitSection` and list `each` remove the reason `itinerary` and
`steps` needed a conditional model.

## What lands

Nine items in three groups:

- **Markdoc and indentation** (4):
  - {% ref "WORK-640" /%}: upgrade from 0.4.0 to 0.5.10;
  - {% ref "WORK-645" /%}: one shared `parse` with `allowIndentation`, used by every parse
    site;
  - {% ref "WORK-657" /%}: `refrakt format`, which re-indents by SPEC-170 D5 (indent only a tag
    that holds another block tag), with `--check` in CI and editor formatting;
  - {% ref "WORK-658" /%}: `site/content/` migrated by the formatter.
- **The composition parser** (4):
  - {% ref "BUG-038" /%}: compile `itemModel` patterns;
  - {% ref "WORK-646" /%}: the delimited model with fixed zones;
  - {% ref "WORK-647" /%}: `implicitSection`;
  - {% ref "WORK-648" /%}: `each` over a list's items.
- **Config** (1): {% ref "WORK-649" /%} gives `sequence` a modifier source, which deletes
  `plot`'s `postTransform`.

## Sequencing inside the milestone

- WORK-640 → WORK-645 → WORK-657 → WORK-658. The "no existing parse changes" measurement is
  re-taken on 0.5.10.
- BUG-038 before WORK-648. They touch the same part of the resolver.
- WORK-646, WORK-647 and WORK-649 are independent.

So three tracks can run in parallel: Markdoc and indentation, the parser, and the config. The
first track is the longest chain, so it should start first.

## Deliberately not here

- **SPEC-169 D1's composed `hero` fixture.** It needs `section`'s split and `actions`, which
  are v0.43.0's ({% ref "WORK-654" /%}). WORK-646 proves the model over `card`.
- **SPEC-169 D5**, templates covering several values. It waits on {% ref "SPEC-168" /%}'s
  templates as tags.
- **A composed `plot`.** {% ref "SPEC-169" /%} D6 sends a composition's sequence styling to
  {% ref "SPEC-156" /%}'s ladder, which is still draft.
- **`section` as the composition base** ({% ref "SPEC-160" /%}): v0.43.0.
- **Theme and site templates** ({% ref "SPEC-177" /%}): its prerequisites are listed in the
  spec, and two of them are unbuilt.
- The `segmented` model, `storyboard`'s move to core, and the decision to swap the storytelling
  plugin for the composed runes ({% ref "SPEC-147" /%}).
