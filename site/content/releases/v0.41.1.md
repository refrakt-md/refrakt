# v0.41.1 · Readable release notes

Released October 16, 2026 · [All releases](/releases)

The changelog on the site is now a list of short summaries, one per release, saying what each
release is for. Every release has its own page with the specs and bugs behind it as drawers and
the full list of changes ({% ref "SPEC-176" preview="drawer" /%}). This release also fixes `plan validate --against`, which missed an ID
collision with anything `main` created after a branch split off ({% ref "BUG-040" preview="drawer" /%}), and
`plan create milestone`, which named the file after the title instead of the version
({% ref "BUG-041" preview="drawer" /%}).

## Changes

- An open drawer on a page using the default layout now reaches the top and bottom of the viewport. The layout's section spacing (`* + [data-rune]`, 4rem above and below each rune block in an article) also matched the drawer's `<dialog>`, which the drawer pipeline places at the end of the article, and its specificity beat the drawer's own `margin: 0`. The panel therefore stopped 4rem short of both edges. Both section-spacing rules now skip `dialog`, so prose after a closed drawer gains no gap either. The no-JS fallback, a `<section>` in the flow, keeps its spacing, and docs-layout pages were never affected.
- `refrakt plan validate --against <ref>` now catches the collision it was built for: an ID the base branch took after your branch split off, while your branch took the same one. It used to read any base file missing from your working tree as one your branch had deleted, which also skipped every file the base added later, so two branches that each claimed the next free ID passed with "No ID collisions".
- The check now reads the merge-base of `HEAD` and the ref. A base file that existed there and is gone from your tree was deleted or renamed by your branch, and is still not a collision; one that did not exist there is. A file the base renamed or deleted after the branch point is not a collision either.
- Because it needs the merge-base, a ref with no shared history, or a shallow clone that stops short of it, is now an error rather than a clean run. Fetch the history first (`git fetch --unshallow`, or `fetch-depth: 0` with `actions/checkout`).
- `refrakt plan create milestone --id v1.2.0 --title "…"` now writes `milestones/v1.2.0.md`. It used to name the file after the title (`milestones/<title-slug>.md`), contrary to the convention that a milestone's filename is its name, and two milestones with the same title could not both be created. `plan init`, and so `create-refrakt --type plan`, now writes its example milestone as `milestones/v0.1.0.md` instead of `milestones/first-release.md`.
- `refrakt plan migrate filenames` now renames a milestone whose filename is not `<name>.md`, so a plan directory that picked up title-named milestones can be repaired with `--apply --git`. It used to skip milestones entirely. Its result no longer has a `skipped.milestones` count; milestones are counted under `skipped.alreadyCorrect` or planned like any other file.
